One core. Three frameworks. Zero drift.

Foolscap ships design as four layers: tokens, styles, a headless behavior core, and thin framework adapters. Scroll to trace one real component — Tabs — start to finish.

Stage 01// tokens

One JSON file owns every color.

Design decisions live in one token file, not sprinkled through 60 components. Change a value once and every layer above inherits it.

▸ packages/tokens/src/palette.tokens.json

{
  "paper":     { "$value": "#FBFBF9", "$type": "color" },
  "ink":       { "$value": "#1A1A1A", "$type": "color" },
  "ink-muted": { "$value": "#5C5C5C", "$type": "color" },
  "grey-500":  { "$value": "#737373", "$type": "color" }
}

// one token, many surfaces — never hard-code a hex in component CSS.

The gate// how much JS does this need?

Every component answers one question first.

Tier 1 is CSS-only. Tier 2 is a native element plus a thin shim. Tier 3 needs a real state machine. Tabs' real answer: Tier 3.

▸ PRD §7.1 — the three-tier strategy

// tier 1 -- css only, no js   (target: ≥60% of 60)
Button · Badge · Card · Table …
// tier 2 -- native element + thin shim
Accordion · Modal · Popover · Toggle
// tier 3 -- headless machine required
Tabs · Combobox · Select · Toast

// route by what the platform already gives you, not by habit.

Stage 02// css, the paper skin

Every color, one line of CSS.

tabs.css never writes a hex code. It reads tokens through custom properties, with the paper skin's own fallback baked in.

▸ packages/css/src/components/tabs.css

@layer foolscap.components {
  .fc-tabs__tab {
    color: var(--fc-ink-muted, rgb(26 26 26 / .6));
  }
  .fc-tabs__tab[aria-selected='true'] {
    border-bottom-color: var(--fc-ink, rgb(26 26 26));
  }
}

// no hard-coded colours, spacing, or type sizes in component CSS — the PRD's own lint rule.

Stage 03// core, the headless machine

Zero framework imports. All the behavior.

createTabs() owns state, keyboard handling and ARIA. React, Vue and Angular never see any of this logic — only its output.

▸ packages/core/src/tier3/tabs.ts

import { createStore } from '@web-loom/store-core'
export function createTabs(options = {}) {
  const store = createStore({ value, focusedValue }, ...)
  return {
    getTabProps(value) { /* role, aria-selected, onKeyDown */ },
    getPanelProps(value) { /* role, hidden */ },
    subscribe: store.subscribe, destroy: store.destroy,
  }
}

// zero React/Vue/Angular imports at the top of this file — that's the whole guarantee.

Stage 04// adapters, one core, three idioms

Three frameworks, one call to createTabs.

React's hook, Vue's composable, Angular's injector — different plumbing, identical wiring. None of them touch a keyboard event.

▸ react/Tabs.tsx · vue/Tabs.ts · angular/Tabs.ts

// react -- useMachine + Context
const machine = useMachine(() => createTabs({ ... }))
// vue -- useMachine + provide/inject
const machine = useMachine(() => createTabs({ ... }))
// angular -- injectMachine + InjectionToken
this.machine = injectMachine(() => createTabs({ ... }))

// adapters add no behavior of their own — that would break parity.

Stage 05// tabs, rendered

Three trees. One state. No tell.

Same fc-tabs class contract, same createTabs state, in three different component trees. A user can't tell which framework rendered it.

The drawing, complete

The core is the product.

Tokens decide what it looks like. CSS decides how that paint lands. Core decides how it behaves. Adapters just translate. Every layer inherits from the one below it. That is Foolscap's whole architecture.
